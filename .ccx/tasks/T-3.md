# CLI cache layer + `R` hard-refresh wiring

## Goal

Today `r` (refresh) and `R` (hard refresh) on inbox/issue buffers
do the exact same thing — both re-shell the CLI. Add an in-memory
TTL cache to `lua/redmine/cli.lua` so `r` can serve from cache when
fresh, and `R` always bypasses. This pays off when navigating in
and out of issues, or scrolling between inbox + issue repeatedly.

## Acceptance

- [ ] `cli.lua` gains a TTL cache keyed by argv tuple + relevant
      env (URL+API-KEY hash so cache doesn't bleed across users).
      Default TTLs in `config.lua`:
      - `cache.inbox_ttl_ms = 30_000` (30 s)
      - `cache.issue_ttl_ms = 60_000` (60 s)
      - `cache.enabled      = true`
- [ ] `cli.run(args, opts, on_done)` and `cli.run_json` accept an
      `opts.cache` table: `{key='inbox'|'issue'|nil, hard=false}`.
      - `hard=true` bypasses both read and write — always re-runs.
      - `key=nil` (default) means **no caching** for that call —
        only opt-in callers cache. This matches CLAUDE.md's "no
        speculative features" rule.
- [ ] `inbox.lua` and `issue.lua` `render` paths pass
      `{cache = {key='inbox'|'issue', hard=opts.hard}}` so the
      existing `R` keymap propagates `hard=true` through to the
      CLI layer (it's already wired to `M.refresh(id, {hard=true})`
      — verify the chain).
- [ ] Cache writes happen ONLY on `exit_code == 0`. Errors are
      never cached (otherwise transient auth failures stick).
- [ ] `:checkhealth redmine` adds one new line: `cache: enabled
      (inbox_ttl=30s, issue_ttl=60s)` or `cache: disabled`. Small,
      observable.
- [ ] No CLI subcommand changes. Cache is plugin-local.
- [ ] E2E unchanged for default paths (cache transparent). One new
      assertion: hit `redmine://issue/1` twice in a row, second
      call serves from cache — verify with a counter increment
      inside a thin `vim.system` stub OR (simpler) by setting a
      huge TTL and asserting `cli.cache_stats()` (small public
      helper exposing `{hits, misses}`) shows ≥ 1 hit.

## Context

- `lua/redmine/cli.lua` — current `run`, `run_json`,
  `run_allow_fail`. Async via `vim.system`. Each call is a fresh
  process, no shared state.
- `lua/redmine/ui/issue.lua` already passes `{hard = …}` to
  `render` (M2 plumbing). Read it before changing — wiring may be
  mostly there.
- `lua/redmine/ui/inbox.lua` does NOT yet have a hard-refresh
  separator. Add a similar `{hard}` path if T-1's deliverable
  hasn't already.
- TTL semantics: store `{stdout, captured_at_ms}` per key; on read,
  check `now - captured_at_ms < ttl_ms`. Keep it dead simple —
  Lua table, no LRU, no size cap (the cache size is bounded by the
  set of distinct argvs the plugin issues, which is tiny).
- Env-key hash: `vim.fn.sha256(REDMINE_URL .. '\0' .. REDMINE_API_KEY):sub(1, 16)`
  prefixed to the cache key. Without this, a user who swaps env
  vars mid-session would see stale data from the previous server.

## Out of scope

- Disk-persisted cache. In-memory is sufficient — sessions are
  short, and the alternative (disk) introduces invalidation pain.
- Cache eviction by `:Rmcomment` post → "refresh affected views".
  That's already covered: `compose.lua`'s post handler calls
  `require('redmine.ui.issue').refresh(issue_id)` which (after
  this task) will fire `{hard=true}`. Verify.
- CLI-side caching. Plugin-local is the right layer.
- Configurable cache key strategies. The two keys (`inbox`,
  `issue`) cover everything we cache; meta/list-filtered calls
  stay uncached.

## Test plan

- Manual: `nvim -u tests/minimal.lua -c 'Rm 1'` → `r` → buffer
  re-renders fast (cache hit). `R` → buffer re-renders, network
  hit (you'll see CLI process spawn if you `lsof` or just trust
  the timing).
- E2E:

  ```lua
  -- cache hit on second open of same issue
  vim.cmd('Rm 1')                       -- miss
  wait_until(function() return vim.fn.bufnr('redmine://issue/1') ~= -1 end, 8000)
  pcall(vim.api.nvim_buf_delete, vim.fn.bufnr('redmine://issue/1'), { force = true })
  vim.cmd('Rm 1')                       -- hit (within TTL)
  wait_until(function() return vim.fn.bufnr('redmine://issue/1') ~= -1 end, 8000)
  local stats = require('redmine.cli').cache_stats()
  record('cache produces at least 1 hit on repeated open',
    stats.hits >= 1, ('hits=%d misses=%d'):format(stats.hits, stats.misses))
  ```

- Don't regress existing 33+T-1/T-2 assertions.

## Decisions

- q: "Should cache be opt-in or opt-out per call?"
  a: "Opt-in — only `inbox`/`issue` keys. List/meta/post stay
      uncached. Caching by default would force every caller to
      think about freshness."
- q: "TTL configurable per call vs config-only?"
  a: "Config-only for inbox/issue. Adding per-call overrides is
      speculative."
- q: "Persist cache across nvim restarts?"
  a: "No. In-memory only."
- q: "What if env vars change mid-session?"
  a: "Hash REDMINE_URL+API_KEY into the cache key so swapping
      environments invalidates implicitly."
- q: "Cache list/meta?"
  a: "Not in this task. Only the two heavy view buffers."
- q: "Expose cache_stats() publicly?"
  a: "Yes, small helper for tests and :checkhealth. Document on
      the M.* public surface in cli.lua but keep it minimal."
