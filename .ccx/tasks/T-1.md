# Inbox filter polish — `:Rminbox <filter>` arg + picker

## Goal

Make the inbox's filter selection both **explicit** (one shot via
command argument) and **discoverable** (picker instead of blind
cycle). Today users only have `:Rminbox` + the `f` key cycling
`open → all → mine → open` — the user can't jump straight to
"closed" and has to remember the cycle order.

## Acceptance

- [ ] `:Rminbox` (no arg) keeps current behavior — opens inbox with
      `config.inbox.default_filter` (defaults to `open`).
- [ ] `:Rminbox open|closed|all|mine` opens inbox pre-filtered to
      that value in one shot. Invalid arg → `vim.notify(ERROR, …)`
      with the list of valid values and **no buffer opens**.
- [ ] `:Rminbox` accepts the same custom-completion as `:Rm` does
      today: `complete = function(arg_lead, …) return matching values end`
      so `<Tab>` suggests `open / closed / all / mine`.
- [ ] Inbox `f` keymap now opens a `vim.ui.select` picker with the
      four filter values plus a fifth `cancel`. Picking applies and
      re-renders; `cancel` is a no-op. (The cycle behavior is
      replaced — pickers are unambiguous and don't depend on order.)
- [ ] Inbox header line keeps showing the active filter (already
      does). No format change required.
- [ ] `tests/run_e2e.lua` gains at least one assertion for
      `:Rminbox closed` → buffer renders with `[필터: closed]` in
      header.

## Context

- Current inbox: `lua/redmine/ui/inbox.lua` — state.filter,
  `FILTER_CYCLE`, `format_lines`, `render`, `bind_keys`.
- Current command registration: `lua/redmine/commands.lua` —
  see how `:Rm` accepts `<id>` arg via `nargs = '?'`.
- CLI already accepts `--filter open|closed|all|mine` — no CLI
  change. Verify with `redmine list --filter closed --json`.
- `config.lua` exposes `inbox.default_filter` and
  `keymaps.inbox_buffer.filter` ('f'). Don't change defaults; just
  honor the existing keymap key.
- Picker convention: existing `lua/redmine/actions.lua` uses
  `vim.ui.select` for status/assignee. Mirror that style for
  consistency (no plenary, no telescope dependency).

## Out of scope

- `:Rminbox --project <id>` — explicitly deferred (user accepted
  "필터만 강화" scope).
- Sort options. Out of scope.
- `:Rmsearch` text search. Out of scope.
- CLI changes. If you think you need one, escalate via `chat_ask`.

## Test plan

- Manual: `nvim -u tests/minimal.lua -c 'Rminbox closed'` →
  inbox header shows `[필터: closed]`, list contains only Closed
  issues.
- Manual: `:Rminbox foo` → ERROR notify, no buffer.
- E2E: extend `tests/run_e2e.lua` with one new block:

  ```lua
  -- :Rminbox closed renders header with closed filter
  vim.cmd('Rminbox closed')
  local ok = wait_until(function()
    local b = vim.fn.bufnr('redmine://inbox')
    if b == -1 then return false end
    local h = (vim.api.nvim_buf_get_lines(b, 0, 1, false)[1]) or ''
    return h:match('필터:%s*closed') ~= nil
  end, 8000)
  record(':Rminbox closed applies filter from arg', ok)
  ```

- E2E baseline must stay 33/33 + new case. Run with the docker
  stack already up at `localhost:13080`:

  ```
  REDMINE_URL=http://localhost:13080 \
  REDMINE_API_KEY=$REDMINE_API_KEY \
  nvim --headless -u tests/minimal.lua -c 'luafile tests/run_e2e.lua'
  ```

## Decisions

- q: "Should `f` cycle or open a picker?"
  a: "Picker. The user explicitly chose 'filter만 강화' with picker."
- q: "Add `:Rminbox <project>` too?"
  a: "No. Project filter is out of scope for this task. Defer."
- q: "What does invalid `:Rminbox xyz` do?"
  a: "Notify ERROR with valid values, do not open a buffer. Match the existing `:Rm abc` pattern (see test 3 in run_e2e.lua)."
- q: "Custom completion for `<Tab>`?"
  a: "Yes — register `complete = function(arg_lead) …` returning matching values. Mirror nvim_create_user_command style; no third-party deps."
